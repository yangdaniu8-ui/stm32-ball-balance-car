# FreeRTOS 迁移与实车验证

参赛作品已完成全部六项竞赛任务并获省级三等奖。本文描述的是赛后 FreeRTOS 重构版本，
其中“尚未实车验证”仅指该重构版，不是否定参赛成果。
个人职责与关键调试取舍见 [工程实践与 AI 协作](ENGINEERING_PRACTICE.md)。

## 改了什么、为什么

| 改动 | 原来的风险 | 新行为 |
|---|---|---|
| 4 个任务，控制周期 10ms | OLED/主循环耗时改变 PID 调用频率 | 显示、通信与控制分离；记录控制超期 |
| 统一参数文件 | 参数散落、旧头文件容易误导 | 速度、时间、水平脉宽、方向、PID 均在 app_config.h |
| 单一路径串口接收 | 中断和主循环争抢 DR、重入解析；ISR 调用 atof | ISR 仅缓存字节与时间戳并通知，VisionTask 解析 |
| 严格数字帧校验 | 错误文本被 atof 当成 0，截断帧可被接受 | 拒绝非法字符、超长帧、±12.5cm 外坐标；错误后丢弃到分隔符 |
| 新帧更新滤波/速度/积分 | 同帧反复滤波、速度静止后残留、虚构 dt | 序号去重，按有效帧间隔计算，静止速度随新帧衰减 |
| 重置控制器 | 急停/重启带入积分、前馈、滤波状态 | 每次启动、回 IDLE、故障都重置 |
| T1 结束保持 −5cm | 5s 后目标回 0 且 PID 停止 | 计时冻结但保持环继续运行；START 可退出 |
| 直接启动计时 | 3s 倒计时与赛题启动计时口径不一致 | START 短按确认事件后开始，软件扫描/调度分辨率约 10ms |
| 长按释放抑制 | 读走 LONG 后松手被误认成 SHORT | 长按状态独立记录，松手不产生短按；START 长按不连发 |
| 视觉/丢线故障 | 旧坐标无限使用，全白被当成中心 | 视觉超过 250ms、连续丢线 300ms 停车；故障需按 START 复位 |
| DWT 延时 | delay_ms 修改/关闭 SysTick | 不碰 SysTick；调度后毫秒延时阻塞任务 |
| 电机斜坡时基复位 | 停机后累计时间可能导致启动跳变、乘法溢出 | Stop/Brake 清时间戳；单次斜坡间隔限制到 20ms |
| OLED 连续帧传输/恢复 | 每字节启动一笔 I2C；总线异常长期卡住 | 连续发送，保留有界等待；恢复时 9 个 SCL 脉冲及 STOP |
| 静态任务和队列 | C8T6 SRAM 有限、运行期分配风险 | 关闭动态分配，开启栈溢出检查、assert、安全停机钩子 |
| 明确 Cortex-M3 移植层 | SysTick/SVC/PendSV 冲突、NVIC 优先级错误 | 官方 RVDS/ARM_CM3；串口 IRQ=6、系统调用阈值=5 |
| 清理编译列表 | 无关示例/旧 ISR/警告混在一起 | 只编译当前使用驱动与必要标准库；源码保留 |

## 重要兼容变化

- 接线、电机方向、10kHz 电机 PWM、50Hz 舵机 PWM、115200 串口均保留。
- 默认水平为 1800μs；校准结果仅 RAM 保存，断电后回默认。
- 取消启动倒计时；RUNNING 短按 START 也可以停机。
- T0=16.6s、T2=8s、T3/T4=28s 是原工程定时参数，仍不是终点检测。
- T0/T3/T4 默认 PWM 2500；T2 独立默认 1700；T1 电机关闭。
- T1 仍按 2.5s 切目标、5s 冻结计时，不宣称 5s 内已实际稳定。
- FINISHED 中 T1～T4 保持相应球目标；丢失视觉时安全回水平。
- 旧头文件中的 LINE_KP/LINE_KD/BAL_RAMP_MAX 不再是调参入口。

## 参数单位与调参顺序

统一修改 USER/APP/app_config.h。PWM 数字不是实际轮速。

1. SERVO_CENTER_US 对应配置 APP_SERVO_CENTER_US=1800。
2. APP_SERVO_INVERT 保留原值 1；仅在架空、不放球时检查方向。
3. APP_SERVO_LIMIT_DEG=12，APP_SERVO_SLEW_DEG_S=60；机械结构安全优先。
4. 位置误差单位 cm，速度 cm/s，积分乘实际秒数。
5. APP_VEL_DAMPING 是钢球速度阻尼，不是速度误差微分；没有盲目增加噪声敏感的加速度微分。
6. 滤波 alpha=0.4、速度 alpha=0.5 每个有效视觉帧更新一次。
7. 循迹 P=50、I=15.7/秒、D=60.5秒，来自旧系数在 10ms 参考周期下的换算；
   旧循环真实频率未知，必须重新调试。不能同时拿旧头文件系数与新系数比较大小。
8. 前馈幅度按该模式的 PWM 启动斜坡缩放，停止/切模式自动清零。
   这是经验前馈，不等于 IMU/编码器测得的真实加速度。

## 按这个顺序重新上车

1. 先运行 tests/run_tests.ps1 和 tools/build_armcc.ps1。
2. 架空后轮、不放钢球，上电观察 OLED、PB13 STBY、PA8 50Hz 波形与 1800μs 中心。
3. 验证 MODE 能完整循环 T0～T4；重复 START/急停/松手不能自行再启动。
4. T0 不接视觉也应可以启动；其他模式无坐标应显示 VISION 故障。
5. 正常发坐标，检查 B: 与 G:，拔掉 UART 验证超时停机；不要以真实滚落钢球进行故障测试。
6. 电机禁用的 T1 先确认左右方向，再调 +5/−5；5s 之后应该继续保持 −5，而不是回 0。
7. T0 低速重新调循迹；验证全白持续 300ms 会停机，误触发时先检查安装高度和输入电平。
8. 再调 T2 起步，最后 T3/T4 转弯与直线。控制周期改变后需重测各模式运行时间。
9. 同时观察 g_AppDiagnostics：控制超期应接近 0，坏帧/串口错误/队列丢事件不应持续增长。
10. stack_free_words 是历史最小剩余栈字数，在 Cortex-M3 上乘 4 得字节数；
    长时间运行并经历所有状态后再决定是否缩减任务栈。

没有实车、示波器或录像，本次不能证明 ≤1cm 球误差或 ≤2cm 停车偏差。
软件软启动也不能保证 TB6612 承受 JGB37-520 堵转电流，仍需电源和驱动电流保护。

## 构建与回退

本次最终验证结果：

- 主控逻辑回归测试通过；按键驱动使用 GPIO 桩单独编译并通过测试。
- GCC 使用 C99、Wall/Wextra/Werror/pedantic 编译测试代码。
- ARMCC 5.06 update 1 完成 27 个源文件的实际编译、链接和 HEX 生成，无编译警告/错误。
- 最终 ROM=20372 字节（约 19.89KiB），RW+ZI=11176 字节（约 10.91KiB），
  包含静态任务栈、队列、UART 环形缓冲、OLED 帧缓冲及启动栈。
- 尚未真机烧录、测量任务栈高水位/PWM 波形，也未验证本次改版的赛道成绩。

当前工程：Keil ARMCC5，C99，MicroLIB，FreeRTOS V11.1.0，静态分配。
USER/ball_car.sct 明确 Flash=64KiB、SRAM=20KiB，越界时链接报错。
本机旧 uVision 后台启动失败，因此使用同机 ARMCC5.06 的命令行完成实际编译/链接，
不是仅进行语法检查；没有自动烧录。编译输出位于 OBJ/FreeRTOSCLI。

原版代码在 ebd04d1。需要原固件时建议在另一个目录检出该提交并重新编译，
不要对包含未保存改动的目录运行 reset --hard。
