# 车载平衡滚球运动控制系统（电赛 H 题）

基于 STM32F103C8T6 的双轮差速循迹小车与视觉钢球平衡装置。
当前版本使用 **FreeRTOS V11.1.0 + STM32 标准外设库 + Keil ARMCC5**；
K230D 识别钢球并发送坐标，STM32 控制 TB6612 电机和 MG996R 舵机。

## 项目成果与版本说明

**参赛作品已完成赛题全部六项任务，获得省级三等奖。**
任务涵盖钢球运动图传、循迹一圈停车、静止往返定位、AB 段行驶平衡、整圈中心平衡及指定位置平衡。

## 硬件与接线（保持原样）

| 模块 / 功能 | 型号 / 接线 |
|---|---|
| 主控 | STM32F103C8T6，72MHz，64KiB Flash / 20KiB SRAM |
| 后驱电机 | JGB37-520 ×2，12V，333RPM |
| 电机驱动 | TB6612；M1=右轮，M2=左轮 |
| M1 PWM / IA1 / IA2 | PB8（TIM4_CH3） / PB1 / PB5 |
| M2 PWM / IB1 / IB2 | PB9（TIM4_CH4） / PB14 / PB15 |
| STBY | PB13 |
| 四路红外循迹，从左至右 | L1=PC14、L2=PB4、R1=PC15、R2=PB12；LOW=黑 |
| 舵机 | MG996R；PA8（TIM1_CH1），50Hz；水平默认 1800μs |
| K230D TX → STM32 RX | PB7（USART1_RX 重映射） |
| K230D RX ← STM32 TX | PB6（USART1_TX 重映射；当前协议仅接收坐标） |
| OLED | SSD1306，128×64，0.96寸；PB10=SCL、PB11=SDA（I2C2） |
| START / MODE / UP / DOWN | PA11 / PA12 / PB3 / PA15 |
| 调试接口 | 保留 SWD；关闭 JTAG，释放 PB3/PB4/PA15 |
| 机械装置 | 25cm PPR 凹槽摆杆、约 1cm 钢球、舵机连杆 |
| 图传 | K230D WiFi RTSP；电脑端显示与录制另行配置 |

电机、舵机使用容量足够的独立电源支路，逻辑信号需共地。
K230D 电源按实际板卡说明接入，不能把其整板供电电压与 UART 的 3.3V 逻辑电平混为一谈。
未增加编码器，也没有修改原电机方向。

## 模式与默认设置

| 模式 | 对应要求 | 当前软件行为 | 默认 PWM |
|---|---|---|---:|
| T0 | 要求2：一圈停车、≤20s、停车偏差≤2cm | 定时 16.6s 停车，冻结时间；舵机始终水平 | 2500 |
| T1 | 要求3：静止 0→+5→−5cm，≤5s、误差≤1cm | 0～2.5s 目标 +5cm，之后 −5cm；5s 冻结计时，继续保持 −5cm | 0（电机禁用） |
| T2 | 要求4：AB 段、≤8s、钢球中心误差≤1cm | 定时 8s 停车，保持中心 | 1700 |
| T3 | 要求5：整圈、≤30s、钢球中心误差≤1cm | 定时 28s 停车，保持中心 | 2500 |
| T4 | 要求6：整圈、≤30s、指定位置误差≤1cm | 定时 28s 停车，保持可设目标（±10cm） | 2500 |

这里的“速度”数值是 PWM 比较值，不是 RPM，也不是 cm/s。
各模式速度分别保存于 RAM；T4 的 UP/DOWN 用于设置目标，其速度默认值在配置文件修改。

**定时停车并非位置定位。** T0 的 16.6s、T3/T4 的 28s 沿用上传工程里的参数，
不等于自动识别一圈，也不保证停车位置；电池、地面、控制周期变化后需重新测量。
当前尚未实现基于编码器距离与启停线融合的可靠终点识别。

## 操作

- IDLE 短按 START：直接开始运行与计时，取消旧版 3s 倒计时。
- RUNNING 短按 START 或长按 START：停车并回到 IDLE；舵机回水平。
- FINISHED / FAULT 短按 START：回到 IDLE；再次短按才启动。
- IDLE 短按 MODE：T0→T1→T2→T3→T4→T0。
- IDLE 长按 MODE：进入舵机校准；UP/DOWN 短按 ±10μs，长按及连按 ±5μs。
- 校准时短按 START：退出，当前水平脉宽只保存在 RAM，断电恢复配置默认值。
- T0/T2/T3 在 IDLE 用 UP/DOWN 短按调速 ±100；T1 电机不运行。
- T4 在 IDLE 用 UP/DOWN 短按调目标 ±1cm，长按/连按 ±0.5cm。
- T1～T4 必须收到最近 250ms 内的有效坐标才能启动；视觉超时会停车并回水平。
- 循迹过程中连续全白达到 300ms（启动 PWM 足够后）进入丢线故障。

## FreeRTOS 架构

| 任务 | 周期 / 唤醒方式 | 优先级 | 职责 |
|---|---|---:|---|
| ControlTask | 10ms | 4 | 唯一状态机与执行器控制者、循迹、钢球控制、电机斜坡、故障处理 |
| VisionTask | 串口中断通知 | 3 | 环形缓冲消费、严格 ASCII 解析、发布最新坐标帧 |
| KeyTask | 10ms | 2 | 消抖、短按/长按/连按，发送按键事件 |
| DisplayTask | 200ms | 1 | 读取一致状态快照；唯一运行期 OLED/I2C 操作者 |

按键事件走队列；坐标和显示快照使用长度 1 的覆盖队列，避免积压旧数据。
任务、队列、Idle 任务均静态分配，关闭动态内存分配。
SysTick/SVC/PendSV 由 FreeRTOS 移植层接管，DWT 用于微秒延时和电机斜坡。
USART1 中断优先级为 6，使用 FromISR 通知，与最大系统调用优先级 5 配套。

钢球位置滤波与速度估计仅在新视觉帧上执行。
速度使用相邻帧的位置差与接收时间差；不对同一帧反复积分。
约 20Hz 视觉不会因为 100Hz 控制任务而变成 100Hz 测量。

## 配置与调试

统一参数文件：[`USER/APP/app_config.h`](USER/APP/app_config.h)。

优先检查水平脉宽、舵机方向和 ±12°限幅，再调静止 T1，最后调移动中的平衡。
循迹积分使用秒，微分除以 dt；原循迹系数以明确的 10ms 参考周期换算，
但旧版循环频率未知，不能声称与原车表现完全一致。
舵机速率限制为 60°/s，前馈是按 PWM 起步斜坡缩放的经验补偿，并非实际加速度测量。

详细变化、参数单位、重新上车验证步骤见 [迁移说明](docs/FREERTOS_MIGRATION.md)。
调试器可观察 `g_AppDiagnostics`：控制超期次数、队列丢事件数、
串口错误、坏帧数，以及四个任务的最小剩余栈字数。

## 编译与测试

### Keil

1. 打开 `USER/AT8236.uvprojx`，目标为 `BallCar_FreeRTOS`。
2. 使用 ARMCC5（本次验证为 5.06 update 1）、C99、标准外设库、MicroLIB。
3. FreeRTOS 源码已随仓库提供，不需要下载子模块；只编译 RVDS/ARM_CM3 移植层。
4. Rebuild；链接使用 `USER/ball_car.sct`，检查 64KiB Flash / 20KiB SRAM 限制。
5. 先架空车轮并移走钢球验证启动/急停，再上车调参。没有自动烧录硬件。

### 命令行

从仓库根目录，在安装 GCC 的 PowerShell 环境中运行：

```powershell
.\tests\run_tests.ps1
```

安装 ARMCC5 后，可从注册表自动定位编译器，或显式传入目录：

```powershell
.\tools\build_armcc.ps1 -ArmCompilerDirectory 'D:\Keil_v5\ARM\ARMCC\bin'
```

命令行构建输出至 `OBJ/FreeRTOSCLI/`，编译产物和测试可执行文件不会上传。
电脑端测试覆盖状态机、五种任务计时、重复启动、计时回绕、视觉/丢线故障、
校准限幅、串口异常帧、控制限幅、重复帧抑制和按键长按释放行为。
这些测试不能替代真机调度、PWM 波形、赛道与钢球误差测试。
